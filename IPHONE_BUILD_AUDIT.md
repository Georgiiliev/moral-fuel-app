## What already works

- Development builds for the iOS simulator and an Android emulator, with widgets on iOS (`WIDGET_TESTING.md`).
- A Release build for the simulator, verified in this audit (see `IPHONE_BUILD_FIXES.md`).

## Blockers for a physical iPhone

1. **Expo login** (owner): EAS builds need an Expo account; `eas init` then writes the project id into `app.json`.
2. **Apple Developer Program membership** (owner): Apple only provisions the App Groups capability for
   paid teams. A free Personal Team cannot sign this app with its widgets.
3. **Apple sign-in with two-factor confirmation** (owner): EAS creates the distribution certificate and
   ad hoc provisioning profiles for both targets during the first build.
4. **Device registration** (owner, on the iPhone): `eas device:create` gives a link or QR code that
   installs a profile on the iPhone so its UDID can be included in the ad hoc profile.

## Chosen route

**EAS internal-distribution preview build** (`npm run iphone:build`): a signed Release build with
bundled JavaScript and the widget extension, installed from a link, running without this computer.
A local Xcode build to the connected iPhone (`npm run iphone:local`) is the fallback once an Apple
team is signed in to Xcode; it needs the same paid team for the widgets.
